# PYNQ-ZU DPU Vitis handoff

`build_vitis_dpu_platform_2022.tcl` is the Vitis 2022.1 XSCT handoff check
for the XSA generated by `fpga/export_pynq_zu_dpu_xsa.tcl`.  It matches the
Vivado/Vitis/PetaLinux 2022.1 DPU 4.0 contract; the older 2024.2 Python-client
experiment is not the active build route.

```powershell
$env:PYNQ_ZU_DPU_XSA = 'C:\pynq_zu_dpu_native_build\pynq_zu_dpu_b512.xsa'
$env:PYNQ_ZU_DPU_VITIS_WORKSPACE = 'C:\pynq_vitis_dpu_2022'
& 'C:\Xilinx\Vivado\2022.1\Vitis\2022.1\bin\xsct.bat' .\build_vitis_dpu_platform_2022.tcl
```

The workspace must be a new, short Windows path. The script builds an A53
`standalone` platform so Vitis validates the XSA, processor and BSP handoff.
It intentionally does not create a DPU inference application: a Logitech C270
uses PS USB and Linux UVC/V4L2, and native DPU execution requires a matching
Linux device tree, CMA, DPU driver, VART runtime, B512 `arch.json`, and INT8
`.xmodel`. The generated XPFM/workspace is a local build artifact, not Git
content.

The board-side Linux acceptance contract and its read-only verifier are in
[`linux/README.md`](linux/README.md).  It is deliberately separate from this
standalone handoff: Vitis proving that it can parse an XSA does not prove a
PYNQ Linux image has the DPU driver or runtime.
